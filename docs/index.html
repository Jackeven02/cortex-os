cortex — pause across reboots
The idea

You can't supervise what you can't name.

Every hard problem in agent systems today — a run that dies halfway, a tool call you can't take back, two strategies you wish you could try at once, a process that should survive a reboot — is a problem operating systems solved decades ago. We just never gave agents those primitives.

The function model

run(prompt) → result

One shot. No identity across restarts. No way to pause, fork, bound, or restart. Orchestration leaks into YAML you can't debug.

The process model

spawn / fork / signal / wait / checkpoint

A PID that survives across invocations. A log of every syscall. A parent that can bound, kill, and respawn a child — in ordinary async code.

Primitives

A small kernel, borrowed from the best.

Eleven kernel modules. Nineteen syscalls. Three driver interfaces. Everything here has a fifty-year-old precedent — that's the point.

spawn
Start an agent as a real process with a PID, budgets, and lineage.
ps
Inspect the process tree: state, tokens, age.
kill
Thirteen signals, from SIGINT to SIGXCPU.
wait
Block on a child — or bound it with a deadline (ETIMEDOUT).
fork
Cognitive fork: clone a process at its current state, diverge.
diff
Compare two forked branches' syscall logs, from their shared past.
checkpoint
Snapshot the process image to disk, content-addressed.
restore
Re-materialise it as a new PID — after a reboot — with memory intact.
trace
Every syscall, enter/exit/trap, in an append-only .crec log.
attach
Follow a running process's syscall stream, like tail -f.
limit
Token, USD, and wall-time budgets per process.
daemon
Register a long-lived agent to start on boot and restart on failure.

Quickstart

Run a supervision tree in a minute.

No API key needed — the mock driver is deterministic, so it reproduces identically in CI and on your laptop.

# clone, install, build
git clone https://github.com/Jackeven02/cortex-os
cd cortex-os && npm install

# use the deterministic mock (no network, no key)
unset OPENAI_API_KEY DEEPSEEK_API_KEY

# a planner that supervises three coders
npx tsx src/cli/index.ts spawn \
  --role planner --module ./examples/supervision-tree.ts

# and everything else
npx tsx src/cli/index.ts ps
npx tsx src/cli/index.ts attach 2
npx tsx src/cli/index.ts diff 2 3
// an agent is a module with a default export
import type { CortexContext } from 'cortex-os';

export default async function agent(ctx: CortexContext) {
  // spawn a child, bound it, act on the timeout
  const { pid } = await ctx.spawn({
    role: 'coder',
    agent: { module: import.meta.url }, // absolute!
  });
  try {
    await ctx.wait(pid, { timeoutMs: 8000 });
  } catch {
    await ctx.kill(pid, 'SIGKILL');   // restart policy, in one line
  }

  // snapshot the process image and suspend
  await ctx.checkpoint({ tag: 'before-risky-edit', detach: true });
}

Honest about what v0 is. A checkpoint captures the process image — state, memory, budgets, lineage — not the live JS call stack, so a restored agent re-runs from the top and skips completed work via a memory marker. attach follows the on-disk syscall log; the interactive send-half lands with a first-class daemon.
