# v0.1.1 — Cortex

**A one-defect patch.** The kernel, the syscall ABI, the CLI surface, the drivers
and the state model are untouched — behaviour is identical to `0.1.0`.

## What was wrong

`cortex --version` and `cortex help` printed `cortex v0.0.1`, while the package
manifest and the registry both said `0.1.0`.

The version had been written out by hand in three places: the `VERSION` constant
in `src/index.ts`, plus a literal banner in each of `src/cli/index.ts` and
`src/cli/commands/help.ts`. `package.json` was bumped for the release; all three
were missed. Nothing in the kernel or the ABI was affected — only the number the
CLI reported about itself.

## What changed

- **`VERSION` is now read from `package.json` at load time.** One source of
  truth, so the two cannot disagree again.
- **The smoke check that should have caught this is no longer toothless.** It
  used to assert only that `VERSION` was a non-empty string — it never checked
  what it contained, which is why a release shipping `v0.0.1` passed 479/479. It
  now compares against the manifest, and fails if either CLI banner reintroduces a
  hardcoded `cortex v<x.y.z>` literal.

## Install

```bash
npm i cortex-agent-os
npx cortex-agent-os help     # → cortex v0.1.1 (ABI 1.0.0)
```

Or from source:

```bash
git clone https://github.com/Jackeven02/cortex-os
cd cortex-os && npm install
unset OPENAI_API_KEY DEEPSEEK_API_KEY
npx tsx scripts/smoke.ts     # 479 assertions, 0 failures
```

**Requirements:** Node 22+. One runtime dependency (`cborg`, for the syscall log).
MIT.

## A note on the package name

The npm package is **`cortex-agent-os`**, not `cortex-os`. npm refuses
`cortex-os` as too similar to the already-registered `cortexos` — the two are
identical once punctuation is stripped — and that guard is only evaluated at
publish time. The repository name and the `cortex` / `ctx` binaries are
unchanged, so the command you type is the same.
