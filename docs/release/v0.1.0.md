# v0.1.0 — Cortex

**An operating system for AI agents.** The first tagged release.

Today's agent frameworks treat an agent as a *function*: you call it with a task,
it runs to completion, it returns. Cortex treats it as a *process* — with a PID,
a parent that supervises it, a log of every syscall it made, and a lifetime that
outlives its caller.

This release is the whole thesis, running: the kernel boots, all seven drivers
ship, the CLI is complete, and three demos run end to end. Everything below runs
offline against a deterministic mock driver — `git clone` and go, no API key.

**Requirements:** Node 22+. One runtime dependency (`cborg`, for the syscall
log). MIT.

```bash
git clone https://github.com/Jackeven02/cortex-os
cd cortex-os && npm install
unset OPENAI_API_KEY DEEPSEEK_API_KEY   # fall back to the deterministic mock
npx tsx scripts/smoke.ts                # 479 assertions, 0 failures
```

## What's in it

**The primitives.** `spawn` · `ps` · `kill` (13 signals) · `wait` · `fork` ·
`diff` · `checkpoint` · `restore` · `trace` · `attach` · `limit` · `daemon` —
19 syscalls, 11 kernel modules, 7 drivers.

**Three demos, each reproducible from the README:**

1. **Pause across reboots.** A long-running agent checkpoints mid-thought and
   suspends. The machine reboots; the kernel is torn down; the snapshot stays on
   disk. `cortex restore` brings it back as a **new PID** with memory intact —
   and it skips the work it already did. Pause is a process primitive, not a
   prompt trick.
2. **Fork and compare.** A coder reaches a decision point, forks, and the two
   branches each take a different approach. The fork's result records the exact
   byte offset where they diverged, and `cortex diff` aligns only the two tails.
   This is the atom of *agent search*.
3. **Supervision tree.** A planner spawns three coders; one hangs; the planner
   notices via a bounded `wait`, kills it, respawns it, and assembles the
   result. ~40 lines of ordinary `async`/`await`, no orchestrator, no YAML.

```ts
const { pid } = await ctx.spawn({ role: 'coder', agent: { module: coderUrl } });
try   { await ctx.wait(pid, { timeoutMs: 8000 }); }
catch { await ctx.kill(pid, 'SIGKILL'); /* respawn */ }
```

The timeout is an *observation*, not an action — the kernel reports it, and
killing is your call.

## What's not in it

Stated plainly, because a release note that only lists wins is marketing:

- A checkpoint captures the process **image** — memory, budgets, lineage — not
  the live JS call stack. A restored agent re-runs from the top and skips
  completed work via a memory marker. True continuation capture is post-v0. This
  is the sharpest limitation, and it is the one most worth arguing about.
- `attach` is a read-only, disk-based follow-mode trace in this release. The
  interactive send-half needs a first-class long-running kernel.
- Single host, single process. No distribution, no k8s, no cross-kernel IPC.
- Persistence is a flat directory, and `sleep()` doesn't yet do
  `RUNNING → BLOCKED → READY` accounting.

The full, itemised list is in [CHANGELOG.md](../../CHANGELOG.md#known-limitations)
and in [BACKLOG.md](../../BACKLOG.md), not hidden.

## Why not Temporal / LangGraph / k8s?

Short version: Temporal makes a *human-written* workflow durable — the decision
graph is declared up front. LangGraph runs a *static* graph. In both, an agent
that decides at runtime *"spawn three sub-agents, wait, merge"* doesn't fit,
because the spawning **is** the decision. Cortex's bet is that the "graph" is
just the shape the process tree happens to take at runtime.

There is nothing here a determined person couldn't build on top of a durable
execution engine. The bet is that the abstraction — the
syscall/process/signal discipline — is the thing worth getting right, and that
it's small enough to actually read.

## About this version

This is `0.1.0`, and the `0.x` is honest: **the syscall ABI is not frozen.**
A minor bump before `1.0.0` may carry a breaking change to the ABI or the state
model. If you build against Cortex today, pin the exact version. `1.0.0` is where
the ABI freezes and semver starts applying without exception.

Phases 0 through 5 — design, kernel, drivers, CLI, demos, launch materials — are
all covered by this release. Phases are build milestones; this tag is the
release.
