# v0.2.1 — Cortex

**The persistence layout is now the per-process subtree `docs/ARCHITECTURE.md`
§7 always described.** This closes the last of the four v0 gaps (BACKLOG #4).

Every process owns one directory: `processes/<pid>/log.crec`,
`processes/<pid>/meta.json`, and `processes/<pid>/checkpoints/`. `Recorder.open`
writes `log.crec` *inside the process's own directory* (creating it on first
open), so removing a process is `rm -rf processes/<pid>` — its log, its index,
and its checkpoints all disappear together, with no global index left to sweep.

## What changed

### One directory per process

`docs/ARCHITECTURE.md` §7 has shown `processes/<pid>/{log.crec, meta.json,
checkpoints/}` since the design phase. The disk was flat: `processes/<pid>.crec`
+ `<pid>.meta.json` + a single shared `checkpoints/`. That made "delete a dead
process" a three-file hunt and made `CheckpointManager.load()` a directory
listing.

The recorder now takes the process's *own* directory and always names the file
`log.crec` (ARCHITECTURE §7). `boot.ts` passes `join(processesDir, String(pid))`;
the CLI's path helpers (`crecPath` / `metaPath` / `procDir` /
`procCheckpointsDir`) all resolve under it. `CheckpointManager` gained a
`dirFor(pid)` so checkpoints live under the same subtree, and `load()` now scans
the tree (in-memory index → shared dir → each `processes/<pid>/checkpoints/`)
when it must resolve a chainId by search.

```bash
$ tree .cortex/processes
.cortex/processes
├── 1/
│   └── meta.json
└── 1234/
    ├── log.crec
    ├── meta.json
    └── checkpoints/
        └── 2026-09-20T10:23:01Z_<chainid>.csnap
```

The hard part was that the kernel now opens *many* log files in parallel (one
per PID) instead of appending everything into one shared dir, and the smoke
suite's recorder factories originally shared a single temp directory — every
process wrote the same `log.crec` and the checks collided on each other's
frames. The factories now open `join(root, String(pid))`, and the upgrade-path
checks write the old `<pid>.crec` form explicitly to keep exercising the
migration.

### The upgrade path is still read-only-friendly

A home written by a pre-`0.2.1` build is not invalidated. `existingCrecPath`,
`readMeta`, `maxPidOnDisk` and `findCheckpointByTag` all still read the flat
`processes/<pid>.crec` / `<pid>.meta.json` files (and the shared `checkpoints/`)
and fall back to them when the per-process subtree is absent. So an older
`.cortex` upgrades transparently on first read; a fresh one is never written in
the old shape.

`maxPidOnDisk` still scans *both* layouts, because a forked child gets a `.crec`
but no `.meta.json` — counting the raw `.crec` files (in either layout) is what
keeps the PID counter from reusing a dead child's file and silently merging two
unrelated processes into one log.

## Install

```bash
npm i -g cortex-agent-os
cortex help
```

**Requirements:** Node 22+. One runtime dependency (`cborg`, for the syscall log).
MIT. Smoke: 513 checks.
