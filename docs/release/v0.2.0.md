# v0.2.0 — Cortex

**The first release that closes v0 gaps instead of only patching defects.**

Three of these were places where the documents already promised behaviour the
code did not implement. That is worse than a missing feature — the docs are the
thing you would have trusted. Every fix here moves its documents in the same
commit.

## What changed

### `sleep()` parks for real

`docs/ABI.md` §4.6 has always specified `sleep` as
`RUNNING → BLOCKED → READY → RUNNING`, and `docs/COOKBOOK.md` printed that walk
in a code comment. The implementation just awaited a timer and left the process
RUNNING for the entire nap, so `ps` called a sleeping agent *runnable*.

It now walks the walk: the process sits in BLOCKED with
`blockedOn.kind === 'sleep'`, is made READY when the timer fires, and resumes
only once the scheduler has dispatched it again — the same wake-gate handshake
`wait()` and `recv()` use, so the instruction after `sleep()` can never run while
the process is still BLOCKED. `exit` cancels a pending sleep timer.

```bash
$ cortex top
└─ 1235 tester   blocked   0   $0.0000   waiting on a timer
```

### A restored process runs on its own

`restore` returned a process in state NEW, and nothing inside the kernel adopts
NEW — the scheduler dispatches READY, and `reconcile()` only reconciles READY.
So a restored process sat there until something *outside* the kernel walked it
forward. `cortex restore` carried a stopgap that did exactly that; anyone using
cortex as a library had nothing.

`dispatcher.#restore` now walks NEW → READY and enqueues before returning, and
the CLI stopgap is deleted. `CheckpointManager.restoreAs` still mints NEW —
adoption is the syscall's job, so a caller who wants an unadopted process image
can still have one.

### The synchronous syscalls are recorded

`now`, `random` and `on_signal` are synchronous on `CortexContext` (ABI §8), and
the sync fast-path replicated the state gate but appended no `.crec` frame. A
replay therefore had to trust that the injected clock and RNG would hand out the
same values — which only holds if the agent makes the same calls in the same
order.

A sync method cannot await the recorder, so the frame is built **at call time**,
capturing the exact value the caller is about to receive, and queued; the
dispatcher writes the queue at the process's next async boundary — after
everything the body did synchronously, before the next syscall's `enter` frame.
One frame per sync call (`phase: 'exit'`, args and result together), because a
synchronous call has no duration and cannot fail past its state gate.

`budget` remains unrecorded, now **by policy rather than by accident**: ABI §4.8
keeps it out because it is derivable from the syscalls that spent it.
`on_signal` records the disposition *kind* — never the handler, which is a live
closure.

## New: `cortex top`

```
$ cortex top
cortex top — 4 processes · 2 blocked · 1 running · 1 zombie
31.4k tokens · $0.0480 spent · home .cortex

1     init             running   0        $0.0000   0 syscalls
└─ 1234 coder          blocked   12.3k    $0.0190   waiting on a model call
   ├─ 1235 tester      blocked   0        $0.0000   waiting on a timer
   └─ 1236 reviewer    zombie    2.1k     $0.0040   exit 0 (completed)
```

`ps` is a flat table. `top` draws the same processes as the tree they actually
are — who spawned whom, what each is doing, and *what it is waiting on*. It
exists because the hardest thing about cortex is not any one primitive; it is
seeing that a running agent is a process with a parent, a state and a budget,
like any other process on your machine.

`ProcessMeta` gained an optional `blockedOn` so the read-only views can say why
a process is not running. Orphans hang off init instead of vanishing.

## Breaking (allowed under `0.x`)

`BlockedReason` gained a `sleep` variant (`{ kind: 'sleep', until }`). Code that
switches exhaustively over `BlockedReason` needs a new case. The syscall ABI
freezes at `1.0.0`, not before.

## Still open

**The persistence layout is still flat.** `docs/ARCHITECTURE.md` §7 sketches
`processes/<pid>/{log.crec, meta.json, checkpoints/}`; the disk is still
`processes/<pid>.crec` + `<pid>.meta.json` + one shared `checkpoints/`.

This was deliberately not done here. `CheckpointManager` owns a single directory
and resolves a checkpoint by chainId by *listing* it; per-process checkpoint
directories turn `load()` from a list into a search across the tree — a real
refactor with real blast radius, not a rename. Doing it carelessly would risk
the checkpoint / restore / `diff` path, which is the one Demo B depends on.
Tracked in `BACKLOG.md`.
