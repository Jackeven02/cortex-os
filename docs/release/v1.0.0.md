# Cortex v1.0.0 — the ABI freezes here

**The syscall ABI is frozen.** From this release on, a breaking change to the
syscall contract requires a major version bump; additive changes land in a
minor. The rule is written into [docs/ABI.md](../../docs/ABI.md) under "ABI
status".

`0.x` was building the thing and then closing the gaps the documents had
promised. `1.0.0` is a different kind of release: it settles the contract. It
exists mainly to close two things the ABI had explicitly deferred to "v1".

---

## Capabilities (ABI §4.9 — promised by §9.2)

Three new syscalls: `acquire(cap)`, `release(cap)`, `caps()`. Six capabilities
in a closed set:

| Capability | Gates | **Not** required for |
|---|---|---|
| `spawn` | creating any child process | — |
| `kill` | signalling a process that is not yours | **killing your own children** |
| `fork` | cognitive fork | — |
| `tool:dangerous` | calling an `irreversible` tool | every reversible tool |
| `ipc:any` | `send` to a process that is not yours | your children, your group, any channel |
| `admin` | lets `acquire` ignore the grantable pool | — |

A process has two sets — **held** (what it can do now) and **grantable** (what
it may raise later) — seeded at `spawn`, moved by `acquire`, dropped by
`release`.

```typescript
// Least privilege: run unprivileged, escalate for the one call that needs it.
// Spawned with: cortex spawn --role coder --cap spawn --grantable kill
await ctx.acquire('kill');   // recorded in .crec, like any other syscall
await ctx.kill(pid, 'SIGTERM');
await ctx.release('kill');
```

Three decisions worth arguing about:

1. **The default is full privilege, not least privilege.** Every agent written
   before 1.0 predates capabilities; defaulting to empty would turn all of
   them into `EPERM` traps the moment they upgraded. Least privilege is opt-in —
   `SpawnOptions.capabilities` / `grantable`, or `cortex spawn --cap` /
   `--grantable`.
2. **Two gates are conditional rather than blanket.** `kill` and `ipc:any` bite
   only for processes that are not your descendant and not in your group;
   `tool:dangerous` only for irreversible tools. A supervision tree can always
   kill the child that missed its deadline — otherwise `kill` would be handed to
   every supervisor and would mean nothing. A narrowed leaf can still read,
   compute and call reversible tools; it is structurally unable to touch the
   outside world.
3. **Escalation is recorded.** `acquire` writes a `.crec` frame, so "when did
   this agent escalate, and what did it do next" is answerable from the log.
   That is why escalation is a syscall rather than a config flag.

Capability state lives on the process-table entry (not beside the dispatcher),
so it survives `checkpoint` → `restore` and appears in `ps`.

## Explicit channels (ABI §4.5 — promised by §9.3)

Two new syscalls: `channel_open(opts?)`, `channel_close(channel)`.

```typescript
const { channelId } = await ctx.channel_open({ name: 'reviews' });
await ctx.send(channelId, review);
await ctx.channel_close(channelId);   // idempotent
```

`channel_open` returns a fresh `ChannelId` — anonymous, or a claimed `name`
(duplicates are `EINVAL`) — so a channel is knowable *before* anyone sends to
it. `channel_close` retires it: queued messages are dropped, parked `recv()`
waiters are rejected `EBADF`, later `send` traps `EBADF`.

**Implicit creation on `send` is kept.** Removing it would break every agent
written before 1.0 — exactly what the freeze now forbids. What changed is that
implicit creation is no longer the *only* way to get a channel, and a typo'd
channel name no longer silently mints a channel nobody reads.

> ABI §10 predicted this would land in `0.2`. It was right about the problem
> and four minor versions wrong about the date — a useful calibration for how
> much to trust the dates in that section.

## 24 syscalls, up from 19

`SYSCALL_NAMES` and every policy table are exhaustive over the new set, so
adding a syscall without updating all seven sites is a compile error, not a
runtime hole.

## Deliberately deferred to 1.1

Collapsing the self-recorded syscalls (`memory_read`, `memory_write`, `send`,
`recv`, `fork`, `checkpoint`, `restore`) onto the dispatcher's single recording
path. Those modules predate the dispatcher and still write their own `.crec`
frames; the on-disk format is identical either way, so this is internal tidying
rather than a contract change — which is why it does not hold the freeze
hostage. `send`'s atomicity depends on the module controlling when it records,
so it is worth doing carefully.
