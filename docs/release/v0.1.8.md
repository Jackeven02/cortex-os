# v0.1.8 — Cortex

**Six releases' worth of hardening, published at once.** npm goes straight from
`0.1.2` to `0.1.8`: `0.1.3` through `0.1.7` exist as git tags but were never
pushed to the registry. If you are on `0.1.2`, this is everything that changed
since.

No breaking changes anywhere in the run. The syscall ABI, the state model, the
CLI surface and the default memory regions are all unchanged throughout — every
one of these was a `patch` bump.

## What changed

**Correctness (`0.1.3`, `0.1.5`).** Nine defects found reviewing `0.1.2`, then
three more from that review's "found but deferred" list — the ones that were
genuine correctness breaks rather than stylistic warts:

- a finite `wallTimeMs` budget never drained, so wall-clock time could never trip
  `SIGXCPU`: a process with capped wall time but unlimited tokens and USD ran
  forever;
- `send()` mutated channel state *before* an awaitable record that can fail, so a
  send that surfaced `ERECORD` could still have been delivered;
- a write destined for `ENOMEM` still paid for — and left behind — a
  copy-on-write split, so a rejected write could diverge a shared region.

**Hardening (`0.1.4`).** A filesystem-driver symlink sandbox escape, and a SQLite
driver region-name collision.

**Memory region ceilings (`0.1.6`, `0.1.7`, `0.1.8`).** The kernel has always
had a per-region write-count ceiling that traps `ENOMEM`, but nothing outside the
kernel could set it, so in practice the guard was unreachable and every region
was effectively unlimited. It is now wired end to end:

```bash
cortex spawn --role hoarder --task "..." --max-region-entries 500   # global cap
cortex daemon run --max-region-entries 500                          # same, supervised

# as of 0.1.8, per region — overrides the global cap:
cortex spawn --role hoarder --task "..." \
  --memory '{"episodic":{"kind":"cow","backing":"inmem","maxEntries":50}}'
```

A region's own `maxEntries` takes precedence over the global ceiling: absent
inherits it, `-1` opts that region out to unlimited, `0+` is a hard cap. The
`ENOMEM` check resolves the effective cap per region and still runs *before* any
copy-on-write divergence. Resolved policies now survive a cross-invocation
`cortex restore`, which also closed a pre-existing latent gap: a custom region
policy set at spawn time used to be silently dropped on restore.

## Install

```bash
npm i -g cortex-agent-os
cortex help
```

**Requirements:** Node 22+. One runtime dependency (`cborg`, for the syscall log).
