**动态 1（主帖）**

今天写 Agent 的方式有个根本问题：Agent 其实是个**进程**，我们却一直当**函数**在用。🤔

函数是：进去一段上下文，出来一个结果，结束。
进程是：有 PID、有父进程管它、干的每件事都有日志、可以暂停、可以 fork、可以明天接着跑。

Cortex 就是把 Unix 1975 年给程序的那套东西，给到 Agent —— `spawn` / `kill` / `wait` /
`fork` / `checkpoint` / `restore` / `trace`。19 个 syscall，纯 TypeScript，MIT。

开源了 👉 github.com/Jackeven02/cortex-os

---

**动态 2（隔几小时，讲那个最打动人的 demo）**

最让我确信"Agent 真的是进程"的，是这个 demo：

一个一直在跑的 Agent，跑到一半自己 checkpoint 然后挂起。
**机器重启，内核全没了。**
`cortex restore` —— 它回来了，是**一个新的 PID**，记忆还在，而且**跳过了已经做完的活**。

暂停不该是 prompt 里的小技巧，它应该是进程原语。这一个 demo 我从头到尾跑通了 ✅

**动态 3（再隔一阵，讲 fork，并诚实收尾）**

还有一个我特别喜欢的能力：**fork**。

Agent 走到一个决策点，`ctx.fork()` 把它克隆一份，两个分支并行试两种方案，
然后 `cortex diff` 从"它们分叉的那个字节位置"开始对齐两份执行日志，挑出更好的那个。

一次把整棵决策树都探索掉。🌳

当然 V0 还有硬缺口，我没藏：checkpoint 存的是进程镜像、**不是活的调用栈**，
所以恢复后是从头跑 + 跳过已完成的部分；目前也是单机。

Repo 和四份设计文档都在这儿 👉 github.com/Jackeven02/cortex-os
